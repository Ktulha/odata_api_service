# API-сервер для работы с 1С по ODATA — план разработки

## Архитектура (общая схема)

```
Клиенты (только GET)                      1С (OData.publish)
     │  Bearer token                             ▲
     ▼                                           │ только sync-воркер ходит в 1С
┌─────────────────────── Роль: app ──────────────────────┐
│  Flask app factory                                   │
│  ├ before_request: проверка bearer при ЛЮБОМ запросе │
│  ├ Blueprint data: /api/v1/entities/<name>/...       │
│  └ Blueprint admin: /admin/v1/*  (роли, токены, …)   │
└───────────────┬────────────────────────────────────────┘
                ▼
     Собственная БД (PostgreSQL / SQLite) ◄── API только сюда
                ▲
┌────────── Отдельная роль: worker ──────────┐
│  Синхронизатор: APScheduler                │
│  + OData-клиент к 1С (httpx), upsert в БД  │
└────────────────────────────────────────────┘
```

**Принципы:**
1. Прямые OData-запросы клиентов невозможны — API принимает только фиксированный набор маршрутов; entity берётся из реестра, а не из URL «как есть».
2. Все данные читаются из собственной БД. 1С трогает только worker во время синхронизации.
3. Доступные сущности ограничены реестром (`is_active`). Если сущность запрещена — она **не кешируется вообще**, ссылки на неё тоже недоступны и в вывод не попадают.
4. Роли: `role ↔ entity` (набор сущностей). Bearer-токен привязан к роли(ам), проверка при любом запросе.
5. Админка — отдельный слой `/admin/v1/*` со своим типом токена (ADMIN): настройка ролей, глобальный/по-ролям доступ сущностей, генерация/revocation токенов, расписание синхронизации, просмотр логов, ручное обновление сущностей.

## Открытые вопросы (решаем строго по одному)

- [x] **Q1.** Стек: ✅ Python + uv + Flask + SQLAlchemy 2.0 + PostgreSQL/SQLite + APScheduler + httpx
- [x] **Q2.** Токены: ✅ собственные opaque-токены (секрет в БД только как SHA-256 hash). Admin и data различаются полем `kind`; бессрочные + опц. срок; отзыв = `revoked_at`. Без JWT.
- [ ] **Q3.** Хранение данных 1С: одна таблица JSONB на сущность vs EAV vs таблица на сущность?
- [ ] **Q4.** Поддерживаемые параметры запроса: $filter/$count/$value — объём?
- [ ] **Q5.** Удаления в 1С: soft-delete маркером vs удаление строк при расхождении?
- [ ] **Q6.** Синхронизация: полная vs дельты; что делать при ошибке загрузки из 1С?
- [ ] **Q7.** Формат ключей ответа: оригинальные имена 1С vs нормализованные snake_case?
- [ ] **Q8.** Структура репозитория: monorepo app+worker или два сервиса?
